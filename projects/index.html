AWS Terraform Multi-AZ Well-Architected

Highly Available WordPress Infrastructure on AWS

A media or content business running WordPress on a single server risks losing revenue every time that server goes down. This project solves that by deploying a zero-single-point-of-failure architecture across three Availability Zones: EC2 Auto Scaling behind an Application Load Balancer absorbs traffic spikes, RDS Multi-AZ with automatic failover keeps the database available in under two minutes, and CloudFront with S3 origin access control reduces origin load while cutting global latency. WAF protects against OWASP Top 10 threats, KMS CMK handles encryption at rest, and SSM Session Manager eliminates bastion hosts entirely. Alarms on p99 latency and 5xx error rate fire before users notice problems.

AWS Organizations Terraform SCPs SSO

Multi-Account AWS Landing Zone

As organizations scale on AWS, a single account becomes a governance and blast-radius problem. This project builds an enterprise landing zone from the ground up: AWS Organizations with four OUs and ten-plus accounts enforced by eight Service Control Policies, blocking root user access, mandating IMDSv2, restricting regions, and preventing public S3 buckets. A Transit Gateway hub-and-spoke topology gives production and non-production workloads network isolation without VPC peering sprawl. IAM Identity Center provides SAML 2.0 single sign-on, and GuardDuty with Security Hub aggregates threat findings centrally. The result is a foundation that a compliance or security team can build on without renegotiating baseline controls.
